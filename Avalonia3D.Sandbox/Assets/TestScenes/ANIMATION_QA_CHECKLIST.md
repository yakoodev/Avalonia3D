# Animation QA Checklist

## Цель
Проверить базовую работоспособность загрузки и воспроизведения анимаций в Sandbox-сценах, чтобы регрессии ловились до релиза.

## Предусловия
- Собран и запускается `Avalonia3D.Sandbox`.
- Доступна тестовая glTF/glb-модель с одной или несколькими анимациями.
- В UI открыта сцена, поддерживающая панель/элементы управления анимацией.

## Шаги проверки

### 1) Загрузка сцены
1. Открыть Sandbox и выбрать тестовую сцену с анимациями.
2. Дождаться завершения загрузки модели.
3. Убедиться, что сцена отрисована без падения приложения и без исключений в логах.

**Ожидаемый результат:** сцена успешно загружена, геометрия и иерархия узлов доступны для последующих шагов.

### 2) Обнаружение клипов в UI
1. Открыть UI-блок анимаций (список/дропдаун клипов).
2. Сравнить количество клипов в UI с ожидаемыми клипами модели.
3. Выбрать каждый клип по очереди.

**Ожидаемый результат:** все клипы присутствуют, корректно именованы, выбираются без ошибок.

### 3) Управление воспроизведением (Play / Pause / Stop / Loop)
1. Нажать **Play** на выбранном клипе.
2. Во время движения нажать **Pause**, убедиться, что поза зафиксировалась.
3. Нажать **Play/Resume** и проверить продолжение с той же позиции времени.
4. Нажать **Stop** и проверить сброс времени/позы по правилам сцены.
5. Включить **Loop**, дождаться конца клипа и убедиться в циклическом повторе.

**Ожидаемый результат:** команды работают стабильно, состояние плеера и визуальный результат синхронизированы.

### 4) Корректность трансформаций узлов
1. Для узлов с анимацией проверить изменение `Position` / `Rotation` / `Scale`.
2. Убедиться, что дочерние узлы наследуют трансформации корректно (без разрывов и «скачков»).
3. Проверить начало, середину и конец клипа на ожидаемые позы.

**Ожидаемый результат:** трансформации интерполируются корректно, итоговые позы совпадают с референсом.

### 5) Unsupported animation channels в отчёте импорта
1. Загрузить сцену, где есть каналы анимации с неподдерживаемыми pointer path или несовместимым типом значений.
2. Проверить `Scene3D.LastImportReport.UnsupportedAnimationChannels` (через debug/log), что для каждого пропущенного канала заполнены:
   - `clip name`,
   - `pointer path`,
   - `target node/material id`,
   - `reason` (`unknown pointer` / `unsupported value type` / `missing binding target`).
3. Проверить короткий summary в UI: счётчик unsupported channels выводится в статусе импорта (в т.ч. когда import не degraded).

**Ожидаемый результат:** unsupported channels явно отражены в отчёте и summary в UI, без ложных пропусков и без падений.

### 6) Явный отчёт по типам каналов в клипе (TRS / Weights / Material / TextureTransform)
1. Загрузить сцену и открыть лог импорта.
2. Проверить, что для каждого клипа есть строка вида `Summary=[Trs=..., Weights=..., Material=..., TextureTransform=...]`.
3. Сверить итоговые категории с ожиданиями по glTF: TRS/Weights для node animation, Material/TextureTransform для pointer-анимаций.

**Ожидаемый результат:** лог явно показывает типы каналов по каждому клипу, и QA может быстро понять, какой тип анимации реально импортирован.

### 7) Специфика `droid/scene.gltf` (глаза)
- Для `droid/scene.gltf` текущий эффект глаз зафиксирован как **morph + emissive fallback**, а **не animated texture**.
- В текущем ассете отсутствуют каналы `KHR_animation_pointer` с `target.extensions` для emissive texture transform, поэтому анимация UV/texture в emissive slot не импортируется.
- Если нужен именно animated texture в emissive slot, ассет должен содержать каналы `animations[].channels[].target.extensions.KHR_animation_pointer` с pointer на `KHR_texture_transform` (например `.../emissiveTexture/extensions/KHR_texture_transform/...`).

## Критерии приемки
- Средний FPS в тестовой сцене не деградирует относительно базового профиля (или держится в допустимом диапазоне окружения QA).
- В процессе проигрывания отсутствуют визуальные артефакты: дрожание, рывки, спонтанные масштабирования, «взрывы» меша.
- Фактическая длительность клипа в UI/плеере соответствует данным клипа (допуск на измерение ±1 кадр).
- Play/Pause/Stop/Loop отрабатывают без зависаний и без исключений в логах.
- После завершения регрессионного прогона не выявлено критических отклонений в трансформациях узлов.

## Примечания по диагностике
- Если входной glTF содержит нарушения спецификации, фиксировать ссылку на отчет glTF Validator и прикладывать файл.
- Для нестабильных результатов (например, плавающий FPS) повторять прогон минимум 3 раза и усреднять метрики.
